# Go rewrite plan for avhn/secret

## Executive summary

Port the CLI, stores, and agent guard into one pinned Go binary while preserving explicit labels and redacting every loaded literal value. Use a real Bash AST, bounded static expansion, and conservative denial where input or shell dialect cannot be certified. Rendered credential files live only under a guard-protected private namespace. Ship git-installed plugins through executable, symlink-safe scripts that download only digest-pinned, provenance-verified release binaries. Cut over Claude Code only when its hook failures block, including a Go crash after launcher exec; retain the existing Codex Bash hook until a verified host supports the same guarantee. Deliver the estimated Unix core first, then gate Windows and optional providers separately; never claim sandbox protection.

## Revision log

1. Launcher: require Claude Code >=2.1.295 and `onFailure: "block"` on every synchronous PreToolUse entry; Codex failure behavior gates cutover.
2. Fallback: replace automatic Bash fallback with fixed denial for detectable pre-exec bootstrap failures; host blocking handles Go crashes; Bash is explicit rollback.
3. Dialect: require a tested host/version/shell contract for string commands; unknown dialect denies the shell call.
4. Keychain: validate and forward `SECRET_KEYCHAIN` identically on put, get and readback.
5. Expansion: add a pre-expansion AST allowlist, scoped HOME/IFS provenance, and accepted-expansion differential cases.
6. Export: restrict M3 to implemented backends with explicit source/destination grammar and collision policy.
7. Operator boundary: deny export/rotate/rename/delete/import to agent hooks; require a separate interactive human invocation.
8. CLI launcher: require an executable POSIX script, symlink-target checkout discovery, and a documented-install integration test.
9. Release identity: define source/checksum/tag sequence, final-tag rebuild, and attestation checks against repo/workflow/commit.
10. Scope and effort: release the estimated M4 Unix core first; give optional M5 Windows, PowerShell, and provider extensions separate gates and estimates.
11. Rendered files: anchor temporary plaintext inside the guard-protected private store and assert all tool adapters deny reads.
12. Bash regression: parameterize CLI test paths so bash 3.2 runs against compat/secret, not the Go launcher.
13. Release activation: commit Claude hook config before source commit S; promote tested tag C without source edits.
14. Commit cadence: require focused tests with each behavior change, including provider and launcher failure modes.
15. Crash policy: bootstrap failures deny in the script; post-exec Go crashes rely on verified host blocking, not impossible launcher recovery.

Planning baseline: repository at `/home/avhn/secret`, revision `d34251f` (2026-10-13). This document is an implementation contract, not permission to change the repository. Preserve the GPL-3.0-or-later license and all existing user-visible behavior unless an explicitly described security tightening is approved. No existing store contents are migration fixtures; use synthetic stores only.

## 1. Product contract and boundaries

- Keep credentials out of agent context through a sanctioned names-only inventory, selected child environment, literal output filtering, and a PreToolUse guard. Never source a store or evaluate an inspected command. This is accident prevention, not enforcement against an adversarial agent with shell access. Keep `get` human-terminal-only, `exec` human/configured-launcher-only, and clipboard reads prohibited. Child argv and environment, process inspection by same-user processes, malicious executables shadowing trusted names, transforms/substrings of values, MCP/hosted tools, and unsupervised external consumers remain outside the guarantee.
- New protection: parse Bash syntax with an AST rather than the hand-written tokenizer; deny syntactically opaque risky shell requests rather than silently allowing them; handle known assignments, substitutions, file-role flags, and script bodies more accurately; supervise a child process group and stop it on filter failure; ensure failures never fall back to unfiltered child output. Strengthen file identity checks for symlinks and bounded search. Do not claim that static parsing can understand `eval`, aliases, shell functions, arbitrary sourced code, runtime-expanded paths, or interpreter semantics. An agent able to invoke new tools or write and run a custom program can bypass this guard.
- Explicit `--env`/`--label` only, never `NODE_ENV` or ambient environment inference. All nonempty values loaded from every file and every registered keystore record, including unselected sections, are filtered during `run`. Missing registered keystore entries abort before child launch. Only selected keys enter the child; known unselected store keys are removed from inherited environment.
- Security descriptions must say exactly which tool adapters and shell dialects are guarded. Reject unsupported shell dialects until the dedicated adapter exists. Never treat a parse failure, elapsed budget, inaccessible path, or incomplete scan as a proof of safety. An empty/malformed hook envelope may yield no decision for host compatibility, but typed supported tool calls with invalid or missing security-relevant fields deny with a fixed names-only diagnostic. Log no input command, store value, or provider stderr. A missing, untrusted, crashed or timed-out hook can bypass this layer if the host does not itself block failures; never describe such a host installation as fail-closed.

Evidence: `README.md:19-27`, `SECURITY.md:9-77`, `skills/secrets/SKILL.md`, and test matrices. Git history from `31cf3f9` through `d34251f` records fixes for atomic mode/locking, redaction failure, bounded indirection, rg scope/config, parser differentials, symlinks, labels, provider transport, and Codex. Treat those fixes as non-regression gates rather than optional enhancements.

## 3. Hook decisions, from input to result

Adapters decode bounded JSON from stdin, disallow trailing JSON and duplicate security-relevant keys, validate field types/controls, retain cwd/workdir as supplied, and emit either no decision or exactly one host-compatible JSON `hookSpecificOutput` denial. Claude matches Bash/Read/Grep/Edit/Write. Codex matches Bash/apply_patch; its installed plugin currently uses `${PLUGIN_ROOT}` and a 5 s timeout; manual template uses an absolute checkout path. Shell command may be a string or argv array. For argv, inspect tokens directly except recognized `bash|sh -c|-lc` commands whose code is parsed; never join argv into executable source. For string-valued `Bash`, the payload itself does NOT identify the executing shell: require a host-version-and-platform contract validated against actual Claude/Codex calls (including shell executable/config and cwd) before selecting LangBash or LangPOSIX. The envelope `tool_name: Bash` alone is not a dialect signal. An unrecognized/overridden shell, missing dialect proof, Windows PowerShell/CMD or Zsh source denies shell calls with a fixed explanation; never parse them as Bash by guess. Record allowed host/version/shell combinations in test fixtures and repeat actual-host integration on each supported upgrade; if shell configuration can change per command without appearing in the payload, do not enable that host's shell adapter. `tool_input.workdir` overrides envelope cwd where supplied, relative to that cwd. Codex currently omits per-command workdir, so a relative input whose workdir cannot be certified denies content-producing shell calls rather than relying on protected-looking spelling; otherwise do not claim relative-path coverage, and require a corrected host payload to enable the stricter guarantee. Apply_patch checks Add/Update/Delete/Move to headers, both old and new paths, even if patch syntax is malformed; never inspect or repeat value-bearing patch body. Tool path fields are checked lexically and by filesystem metadata only.

Hook-host failure contract (verify again at the version pin, not just unit-test JSON): [Claude Code hook reference](https://code.claude.com/docs/en/hooks) and [changelog](https://code.claude.com/docs/en/changelog) document `onFailure: "block"` from v2.1.295 for synchronous command hooks: missing executable, unexpected exit, invalid output and timeout block `PreToolUse`; default is `continue`. Exit 0 with valid denial JSON is normal denial; exit 2 with a stderr reason blocks; other exits block only with the setting. `hooks/hooks.json` currently has a 5 s timeout and no `onFailure`, so does **not** fail closed on launcher failure. Both Claude PreToolUse groups in the Go-plugin manifest must set `onFailure: "block"`, retain 5 s timeout, and enforce/verify Claude Code >=2.1.295 at installation; older clients cannot be claimed protected (do not ship a Go-only cutover for them). The same applies to every manual Claude hook entry. [Codex PreToolUse source](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/pre_tool_use.rs) initializes `should_block=false`: runner errors, exit 1, malformed JSON and timeouts become `Failed` without blocking, while a valid deny JSON or exit 2 with stderr and control effects blocks. [Codex command runner](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/engine/command_runner.rs) returns `error: Some("hook timed out...")` with no exit code after its deadline; killing the child does NOT block dispatch. As of this source revision Codex has no verified fail-closed failure mode; its [opt-in failure-mode request](https://github.com/openai/codex/issues/41979) is not an implementation. A Codex Go-only cutover is therefore **gated**, not assured by returning denial on normal errors: require a verified host release/config that blocks spawn errors, crashes, invalid output and timeouts, plus tests in that host; until then document host fail-open and keep an explicitly installed/verified hook, without claims of fail-closed coverage. A launcher cannot compensate for a host that never starts it.

Use `syntax.NewParser(syntax.Variant(syntax.LangBash))` for Bash and `LangPOSIX` where shell is explicitly `sh`; recursively walk `Stmt`/`CallExpr` plus pipelines, assignments, redirections, here-doc substitutions, compound statements, command/process substitutions, subshells, functions when defined in text, and static `bash|sh -c` strings. Don't call the `interp` package. `expand.BracesSeq` with an enumerated cap handles Bash braces. `expand.Fields` is a **full** expander, not a sanitizer: [upstream expand API](https://pkg.go.dev/mvdan.cc/sh/v3/expand) includes parameter, arithmetic, tilde, field splitting, command/process substitution and glob expansion. BEFORE calling Fields or BracesSeq on each word, recursively allowlist only `Lit`, `SglQuoted`, `DblQuoted` containing allowlisted child parts, bounded `BraceExp`, and `ParamExp` whose node is exactly an unmodified `$HOME`/`${HOME}` or `$IFS`/`${IFS}`; allow a leading `~` only with a proven fixed HOME. Reject all other `ParamExp` operators/special parameters, arithmetic, `CmdSubst`, `ProcSubst`, extglob/eval-like syntax, and unsupported AST parts as indeterminate at the expansion boundary; separately walk substitutions as commands without using their output as a filename. Use `expand.Fields` ONLY after that AST allowlist, with a synthetic, read-only `Env` containing _proven_ HOME and IFS values, `NoUnset=true`, and nil `CmdSubst`, `ProcSubst`, `ReadDir2`/`ReadDir`, with output/step caps. No inherited user env values enter this Env. Track literal HOME/IFS assignments and wrapper env changes per lexical command scope; inherited IFS is not assumed to equal Bash's default and `$IFS` is indeterminate unless a literal, fully known IFS is established by verified host configuration or preceding scope-local assignment (including its exact splitting bytes). Dynamic HOME/IFS assignments, `env -u/-i`, `sudo`, unknown nested shell inheritance and missing provenance invalidate the corresponding expansion. Paths like `$HOME/` can be recognized only with proven HOME. Verify that Fields does not perform an unapproved transformation for each allowlisted shape; otherwise use a smaller dedicated evaluator for that shape. Explicit safe glob candidates use metadata-only `filepath.Glob` under a match cap; never shell out for word expansion. Preserve quote, escaped-dollar and literal/active provenance in each word, so prose mentioning a store is not a file operand and an active unresolved operand is not misclassified. Inspect substitution AST separately; do not use its printed output as a resolved filename. Keep `cd`, `env -C`, `git -C`, tar -C and wrappers in scoped effective-directory state; no hidden global mutation from subshells or pipelines.

Roles are data tables with explicit option arity and attached/equal flag forms, not a list of inherently safe commands:

- File-content readers: `cat`, `head`, `tail`, `sed`, `awk`, `grep`, `rg`, `jq`, interpreters, `dd if=`, `openssl -in/-inkey`, `git show/diff/log/blame/cat-file`, `tar` extraction/list, `cp/mv/ln` source, `rsync/scp` source, `find -files0-from/-exec`, `xargs -a`, `wc/sort` list files, etc. Unknown command positional protected file inputs default to deny; output targets and plain metadata names are not input. Any input redirect or here-doc substitution is analysed.
- Printers: env/printenv/export/set/declare/compgen, credential-variable echo/printf, ps environment options, jq `env/$ENV`, `gh auth token`, gcloud token, aws configure secret/get/export, `op read/item get --fields|--reveal`, pass show, secret-tool lookup/search, `security ... -w/-g`, kwallet-query, clipboard paste, `secret get/exec`; nested/wrapped equivalents are denied. Allow only an AST-verified _direct stdout pipe_ into valid `secret stash [labels] FILE KEY` for approved printers; `secret-tool search` and `security -g` remain always denied. Any stdout redirect/tee/extra stage invalidates exemption. `secret run` is permitted, but inspect its child syntax and deny protected file reads inside it.
- Metadata/name-only: `ls/stat/test/realpath/readlink/chmod/chown/rm`, `find -name/-print` without content-reading children, `git check-ignore/ls-files/status` except verbose file content, and names-only `rg -l/--files` or Grep files_with_matches. Source-bearing options are still checked before declaring an operation metadata-only.
- Consumers: `docker run/compose --env-file`, dotenv `-e`, node `--env-file`, with accurate option arity and child-command recursion; deny printing child `env`, `printenv`, `docker compose config`. Unknown entrypoint or option arity is indeterminate, not permission. Wrapper table includes env, sudo, timeout, nice, nohup, exec, stdbuf, caffeinate, xargs and command/builtin.
- Interpreter inline code: check active literal credentials, known file APIs and environment getters in Python/Perl/Node/Ruby, and inspect script path operands. Do not execute inline code; opaque dynamic code with a protected witness or direct environment-output risk denies. For JavaScript/Python/etc without a static witness, note residual risk rather than claiming full interpreter coverage. `eval`, aliases, functions from unknown files and unknown `-c` dialects deny when not provably names-only under the configured risk policy.

Analysis budget for default Bash analysis: max 64 KiB JSON, 40 KiB shell source per recursive fragment, 128 lexical words, 64 brace alternatives, 4 nested command-code levels, 200 glob matches, 12 scan levels, 200 ms shared metadata-scan deadline, and 2 s hook internal total deadline (below existing 5 s host timeout). The default build now uses the same bounded AST path without a build tag. The 64 KiB envelope and 40 KiB source ceilings admit the existing 33,000-byte safe-command corpus while remaining bounded; protected-path and printer witnesses above the earlier 8 KiB boundary still deny. Process-launch-inclusive p99 measurements and reviewed differences are recorded in `hook-tightening.md`, separately from the 5 s host limit. Budget/error returns typed `indeterminate`; supported tool calls with protected syntax, unsafe output, or content searches deny. Adopt a fail-closed default for all _indeterminate content-producing operations_ while allowing clearly metadata-only or unrelated inert commands; compare false positives with bash fixture corpus before cutover. Scan only names/metadata, never store bytes. Symlink-check ancestors and final component, including dangling aliases; canonicalize existing roots, fold ASCII protected basenames regardless of filesystem case, reject links/root escapes that cannot be resolved. Avoid TOCTOU promises; unrelated host writes can race the hook.

Search contract: `Grep` content/count checks explicit target and a bounded names-only tree walk; names-only outputs may list names, never content, except exact protected file selectors are denied. `rg` content/count defaults to cwd unless explicit paths; inspect pattern-file inputs, positive globs/type filters, `--hidden`, `--no-config`, `--no-ignore`, `-uu`, `--follow`, archive preprocessors, ignore-file and all scope-changing flags. Honor config only after whole-file size/byte certification, no positive glob re-inclusions or scope-changing flags, and full required case-insensitive negative globs from `examples/ripgreprc`. Config cannot certify explicit protected file roots, `-f` aliases, `/`, `/proc`, or untrusted inline env changes. Without certification scan every explicit/implicit root, deny incomplete/deep/inaccessible searches; names-only `rg -l` remains available. `git grep` has no rg-config exception, recognises `--` path separator, repeated `git -C`, global options, revisions/trees and `-f`, treats unknown refs/options as uncertain, and scans possible input scope; names-only exception must not mask pattern-file reads. Preserve `.git/node_modules` pruning only where tool flags genuinely exclude them; scan vendor and explicit/hidden roots.

Differential protocol: snapshot bash guard at a fixed git revision in test fixtures or run it from its retained executable, feed identical synthetic JSON, cwd, PATH and rg config to both hooks, compare allow/deny and fixed denial shape, classify each difference as intentional tightening, parser grammar limitation or regression in a checked-in reviewed expectation table. Add paired accepted-expansion cases: single/double quotes and escaped dollars, literal `$HOME` with known home, `IFS` explicitly assigned to space/tab and used unquoted vs quoted, brace fields and ranges under the cap, literal tilde, simple globs resolving only synthetic paths, and scoped env -C/cd; compare actual safe Bash argv/paths and Go classifications. Add unknown-inherited-IFS and dynamically reassigned-HOME/IFS deny cases. Also run real `bash -n`, `bash -c` word/trace experiments in a disposable synthetic directory for tricky quoting, brace, heredoc, substitution, IFS, options and redirects: never execute inspected untrusted strings or real credentials. Fail CI on a new unclassified difference. Preserve host output contract while explicitly documenting intended change from the bash guard's fail-open malformed/analysis behavior.

## 4. Store format and CLI compatibility

Port exact bash reader behavior before adding formats: default `~/.secrets.env`, `~/.secrets/*.secret` and hidden files, ignore backup names, `SECRETS_ENV/SECRETS_DIR`, bare NAME resolution (existing local file first, then visible/hidden private file), `file:PATH` escape, `keychain:NAME`/`libsecret:NAME`, key regex, comment and ignored-line warnings, duplicate last-wins, optional leading `export`, first `=`, CRLF removal on each line, matched outer quote pair removal without shell unescaping, malformed starting quote ignored, and no evaluation. `show` without selectors preserves order and duplicate records in labeled files; unlabeled flat stores show last per key; selected `show` displays `<unset>` for unmatched names and canonical sorted labels. Header is _exactly_ `[name=value,...]` (no whitespace, duplicate names invalid); `[]` resets scope; malformed bracket lines are ignored without changing scope. Values can contain literal `$`, `#`, `=`, backslashes and internal spaces; use byte lengths, not rune counts. Document precise parser behavior with golden fixtures including invalid UTF-8 on file stores where Go strings alone would obscure byte semantics.

Selection: labels are explicit AND selectors; equal repeats accepted, conflicting repeats fail; eligible record's labels must be a subset of selector pairs, highest cardinality wins, distinct equal-cardinality winners fail, same identity last wins. Later files replace earlier matched keys, but unmatched keys from later files do not overwrite prior matches. `--key` missing/empty is an error, `--optional-key` missing is unset; no key flags means all selected keys. Ambient store keys are removed if unselected; load _all_ parseable values for filtering before deciding exports. `stash` accepts raw or exactly one trailing LF, rejects empty/NUL/CR/internal LF, boundary whitespace and matching surrounding quotes, wraps lone edge quotes for roundtrip; rewrite only exact-label matching assignments while preserving other bytes, CRLF, section order and trailing newline behavior. `get` checks TTY before opening anything. `clip` clears only if unchanged, with timeout and no clipboard read through the agent hook.

Write lock is a direct atomic directory creation (`.write-lock`, token/PID, 3 s, never steal), mode 0700 private directory and sibling temporary directory, file mode 0600 and same-filesystem atomic rename. Refuse symlinked/nonregular targets and symlinked private directory; use handle-relative APIs where available to narrow symlink races, fsync temp and parent before success on supported filesystems. Keep old file intact on errors, clean only owned lock/scratch. Add multi-process crash/recovery tests. No automatic plaintext store conversion or change to its header syntax.

Read/write `secret-manifest-v1\nbackend=<keychain|libsecret>\n` and TAB-separated `KEY`, canonical labels, 32-lowercase-hex random account exactly; validate duplicates, account uniqueness, backend mismatch, mode, regular file, no extra fields and no values. For existing v1 manifests, keep writing v1 under both current backends. Introduce `secret-manifest-v2` only when needed for new providers, with explicit backend ID, UTF-8 metadata grammar, per-record stable random IDs and optional names-only metadata; no values, hashes of values, references containing credentials, timestamps of value use, or metadata corruption fallback into a provider search. `secret migrate --manifest-v2 REF` explicitly locks, validates, makes private names-only backup, atomically replaces, verifies readback and can roll back before publish. Old bash version must never be pointed at a v2 manifest. A failed provider put before manifest publish can leave an orphan; doctor reports names-only count/repair guidance, no blind deletion.

Backend transport: libsecret store via `secret-tool store` stdin and lookup stdout captured in private memory/pipe; Keychain `security -i` receives hex on stdin, `-g` retrieval is parsed privately because `-w` ambiguously hex-encodes non-ASCII, readback byte-match before publishing, preserve the printable UTF-8/no Unicode controls and roughly 1800-byte command limit. Preserve `SECRET_KEYCHAIN`: if set, validate the exact legacy absolute no-whitespace/no-quoting grammar `^/[A-Za-z0-9_./-]+$` before any provider call, and pass that path to both the `security -i` put and `find-generic-password -g` lookup/readback; if unset, use the default Keychain unchanged. The real-provider test must select a disposable explicit keychain, without changing the user's default or search list (`bin/secret:194-199,234-235,287-288`; `tests/test-keychain.sh:32-40`). Never put a value in provider argv, inherited logging, Go panic or error text. Provider operations have deadlines, isolated stderr, cancellation and exact service/account lookup; no provider-wide enumeration for `run`. Load every registered item for keystore run/exec; get/clip load only selected record. Keep stub backend strictly test-only and fail if accidentally configured with real user credentials.

## 5. Secret bytes, child streams and exit semantics

Use `[]byte` from file/provider through validation and a bounded redactor, never `fmt`/`log`/`errors` containing bytes; reserve strings only where Go `os/exec` requires environment `KEY=value` and document unavoidable copies/GC and `/proc`/process-memory visibility. Zero owned byte buffers, source slices and temporary transport on completion where possible; this is best effort, not secure erasure. Set strict max store and secret size (proposed 16 MiB store, 64 KiB per file value, provider-specific tighter Keychain limit) only after golden parity check for existing oversized inputs; explicitly classify new limits as tightening, not silent compatibility. No full output buffering or temp files of raw child stdout/stderr.

Build a byte-oriented Aho-Corasick automaton or equivalent bounded streaming matcher over unique nonempty _all-loaded_ values, longest match at the same start position wins, deterministic fallback order, leftmost nonoverlap replacement with `<redacted>`, independent stdout and stderr state, holding at most max value length minus one bytes at chunk boundaries. Short values, regex metacharacters, overlapping matches, binary child output and incomplete UTF-8 are literal bytes. Cap total loaded pattern bytes/node count and fail before spawning when exceeded. Each stream has its own goroutine; only it writes its filtered destination. Never write an unfiltered chunk in error recovery. On read/write/filter/pipe failure, cancel entire child process group/job, drain the other filtered stream for a bounded interval, emit fixed diagnostic on a separate line, exit 1 even if child exited nonzero; broken stdout consumer is a filtering failure. After direct child exits, wait a bounded 2 s for descendants to close pipes, then terminate group/job, drop any unprocessed output, exit 1. Treat inherited pipe handles and external descendants as limits, not a proof of containment.

On Unix create a new process group, forward INT/TERM/HUP and kill group on failure, reap direct child and stream workers; on Windows use a Job Object with kill-on-close and console control/termination handling. `run` returns direct child status 0..255 or 128+signal when filtering succeeds, 1 for usage/store/provider/filter failures (never shift a known child failure to 0). `exec` bypasses redaction by design, preserves framed stdio/status/signals and replaces process image on Unix where feasible; document Windows non-exec emulation. stdin passes directly to child, never to a filter. Maintain `get` terminal and `exec` guard restrictions independent of process behavior.

## 6. Features, prioritized with threat-model justification

M0/M1 port: list/show/stash/get/clip/run/exec and both providers, exact output/errors/corpus. M2 protection and packaging. M3 operator workflow:

- `import --from dotenv:PATH|op:ITEM|bw:ITEM-ID --into REF [--label ...] [--map FIELD=KEY ...]`: yes, **human interactive only**; `dotenv:PATH` uses explicit quoting rules and the same parser, `op`/`bw` CLI stdout is privately parsed into a selected store. `ITEM`/`ITEM-ID` is an opaque names-only provider identifier, never a secret value or command line; reject unsafe item-reference characters. `REF` is an explicit `file:ABS_PATH` or currently implemented `keychain:NAME`/`libsecret:NAME`. Never accept a value via argv or print imported records; dry-run lists _names/conflicts only_. Require unlocked provider, fixed subcommands, no shell, and explicit field mapping; reject exporters returning unconstrained JSON until parsed and bounded. No implicit import of every item or `NODE_ENV` inference.
- M3 `export --from REF --to keychain:NAME|libsecret:NAME [--env ENV|--label N=V ...] [--key KEY ...] --on-conflict=fail`: yes, human interactive only; source `REF` is explicit `file:ABS_PATH`/`keychain:NAME`/`libsecret:NAME` (no bare ambiguous names), target must differ from source, labels explicitly select records, no selector selects unlabeled records only. Reject missing/ambiguous selected records and duplicate destination `(key, canonical labels)` identities before any value fetch; `--on-conflict=fail` is mandatory in M3, no implicit overwrite or merge. Under destination lock, stream through provider stdin, verify readback, then atomically publish names-only manifest; on mid-batch failure leave previous manifest intact and report names-only orphan guidance, no unverified rollback of overwritten provider records. There is **no** M3 wincred/pass/onepassword target or plaintext/stdout export; enable each only after its M5 backend implementation and real provider tests. `rotate`, `rename`, `delete`: yes, **human interactive only**; lock, prepare new item first, commit names-only manifest, then garbage-collect old account; all statuses names-only, retain names-only rollback record on failure. Never log or back up replaced values. `diff --env A --env B REF`: yes, keys/labels/presence and backend only, **no value comparison or hashes**, since equality leaks value information. `doctor`: yes, metadata-only checks for modes, alias/symlink, hook activation/trust, binary checksum, config certification, backend availability, version compatibility; no provider fetch by default. `audit`: yes, opt-in local 0600 names-only records for operator actions, never hook command, value, child argv, or full provider stderr; rotation cap and disable by default. Test path metadata leakage and permission modes.
- Human invocation boundary: hook role table denies `secret import|export|rotate|rename|delete|migrate` in Bash, nested shell, `secret run` children and Codex shell calls by default; `get`/`exec` remain denied. Operator invokes a verified CLI directly in their own terminal, not via agent tools or a skill-granted exception; require TTY on stdin **and** stdout before opening stores plus an explicit target/key confirmation prompt from the controlling terminal for destructive or value-moving operations, with no `--yes`, stdin prompt piping, or agent-facing JSON mode. A TTY is a UX check, not proof of user identity: the hook rule is the agent-side boundary. Skill text may explain human steps, never authorize a guarded command. When hosts lack reliable hook execution, document the limitation rather than claiming agent denial.
- `run --template-file TEMPLATE`: accept only as an explicit opt-in M3 feature, with **no user-selected output directory**. Render under the fixed, guard-protected `~/.secrets/.rendered/<random-0700-dir>/payload` namespace (not `${SECRETS_DIR}` if overridden elsewhere); require a non-symlinked private `~/.secrets` root, 0700 parent chain and 0600 file on Unix, Windows private ACLs after M5a. The hook classifies every descendant of `.secrets` as protected regardless of basename, follows symlink aliases and denies Read, Edit, Write, Grep content/count and shell reader operands; names-only search never prints contents. ## 9. Windows and shell dialect policy

Guard does not feed PowerShell/CMD into the Bash parser.
