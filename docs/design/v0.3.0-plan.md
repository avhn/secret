Status: planned, not implementation or release evidence. Owner scope approved 2026-10-28. Base:
`3045d4c50509a00d291968adea5f3629974c79f9`, branch `rel/v0.3.0`. This release extends M4 packaging; it does not
complete M4.1 or M5e host evidence.

  a Claude Desktop MCPB, official MCP Registry metadata/publication, and all four plugin/marketplace versions at

  `hooks/guard-secrets`, `hooks/hooks.json`, both Codex hook configs, timeout/matchers, and Go hook output/policy. No
  `onFailure`, Go activation, `compat/secret`, automatic Bash fallback, or installation of real host hooks.
- Do not enable `host-hooks.yml`, model calls, PowerShell production allows, 1Password dispatch, Windows age/pass,
  package-manager submissions or a network MCP transport. MCP registration is opt-in and does not confer hook
  exceptions.
- The reference is `/home/avhn/trello-mcp`, read-only: reuse its setup organization, quoting tests, native packaging
  inspection and OIDC pattern, not its latest-release selection, checksum-only installer trust, direct publication or
  v1-only policy.
- Separate owner checkpoints still govern commits/pushes, tag, draft, publication, installed-manifest/default
  promotion and external metadata. This plan performs none.

## 2. Frozen artifact and source contract

- V=`0.3.0`, annotated signed tag `v0.3.0`, full source SHA S, checksum-only child C. S includes every source,
  template, manifest, workflow, installer and documentation input. C has exactly one parent S and adds only
  `dist/checksums-v0.3.0.txt`. No fixture marker, including symlinks, may appear on disk or in either tree.
- Raw assets: `secret-v0.3.0-{darwin,linux}-{amd64,arm64}` and `secret-v0.3.0-windows-{amd64,arm64}.exe`; no CLI
  archives.
- Additional assets: `secret-v0.3.0-desktop.mcpb` and generated `server.json`. The checksum asset has exactly eight
  name-sorted, LF-terminated records: lowercase SHA-256, two spaces, exact basename; no duplicates, comments, paths,
  extra names or missing final newline. Checksum does not hash itself.
- Attest all eight payloads plus `checksums-v0.3.0.txt`: nine subjects, nine portable `sha256-DIGEST.jsonl` bundles,
  eighteen public assets. Do not recursively hash bundles. Windows cannot use colon filenames; translate names only in
  disposable gh workspaces where supported, or pass a verified portable bundle path directly to `--bundle`.
- Pin Go 1.26.10, `GOTOOLCHAIN=local`, `CGO_ENABLED=0`, `GOAMD64=v1`, `GOARM64=v8.0`, empty GOFLAGS/GOEXPERIMENT,
  GOENV/GOWORK off, and S's timestamp as SOURCE_DATE_EPOCH. Preserve `-trimpath -buildvcs=false -ldflags='-buildid= -s
  -w -X main.version=0.3.0'`; never build release binaries with test tags or embed HEAD/C/current time.
- Build the complete set twice in independent hosted macOS jobs with different absolute paths, private
  HOME/module/build caches and pinned packaging tools. Assemble the universal Mac payload with native lipo; verify
  both exact slices. Canonicalize MCPB ZIP entry order, timestamps, modes, extra fields and compression inputs; prefer
  stored ZIP entries to avoid compressor-version drift. Validate with the locked MCPB CLI. Compare all eight payloads
  and the checksum asset byte-for-byte. Linux/Windows native install jobs consume this integrated candidate set, not a
  locally substituted binary. `tests/test-launchers.sh` can retain synthetic inputs.
- `build-release.sh` becomes the complete assembly driver; document its macOS/lipo/ Node prerequisites. Six-binary
  fixtures remain usable in isolated unit tests, but no partial manifest can satisfy final verification. Generate
  MCPB, then registry metadata from those exact bytes, then checksums. No C field in hashed payloads: embedding C in S
  would create a circular source/checksum identity.
- Restore the annotated local tag after checkout, require its peel to full C, check exact S..C diff and rebuild at C
  using S's epoch. Keep v0.2.0-v0.2.2 dead tags and v0.2.3 history immutable. Update real-provenance rehearsal without
  treating old four-binary provenance as evidence for new Windows or MCPB subjects.

## 3. Installer trust and installation behavior

- New entrypoints are `install.sh` and `install.ps1`. Accept an explicit exact version (`SECRET_VERSION` or equivalent
  flag); omitted means the script's fixed `v0.3.0`, never latest. Validate stable semver strictly, reject conflicting
  pins, and fail on absent/unsupported pinned versions rather than selecting another.
- Require a separately authenticated full C (`SECRET_RELEASE_COMMIT` or flag), obtained from owner release records.
  Documentation can use a labeled placeholder before S; final C belongs in release records, not a post-S source edit.
  Fetch only the requested annotated tag into private scratch, require peel=C, inspect its single parent and
  checksum-only tree delta. Never take C from a binary, downloaded checksums or an unverified attestation field. No
  ambient checkout pin.
- The one-line examples fetch the installer from the exact tag or full C URL, not main/latest. State immediately that
  executing that script trusts GitHub HTTPS, repository ownership/tag governance and the reviewed installer before its
  payload verification runs. A version pin alone is not independent authentication of C. Offer download/review/run and
  the existing trusted-checkout path as stronger options; do not describe piping a script as cryptographically
  verified bootstrap.
- Require gh for every cold production install. This deliberately satisfies verification when gh is available without
  creating a weaker no-gh path: missing gh fails with trusted-channel installation guidance, never a checksum-only
  fallback. Both scripts verify the checksum asset's attestation, its exact bytes against C, strict complete manifest
  grammar, and the selected binary's SHA-256 and attestation.
- Use `gh attestation verify` with repository `avhn/secret`, source-digest=C, signer-digest=C,
  source-ref=`refs/tags/v0.3.0`, GitHub Actions OIDC issuer, exact SAN
  `https://github.com/avhn/secret/.github/workflows/release.yml@refs/tags/v0.3.0`, `--deny-self-hosted-runners` and
  JSON output. Independently check SLSA v1 subject name and digest. Never combine `--cert-identity` with
  `--signer-workflow`, or `--repo` with `--owner`; preserve the existing genuine-provenance regression.
- POSIX bootstrap may reuse the reviewed C checkout's installer after authenticating its identity; no source build is
  performed. Preserve existing trusted-checkout cache, rehash-before-exec launchers, fixed exits/denial JSON and
  offline interfaces. Update their version/checksum grammar, not the installed Bash hooks or defaults.
- New standalone installs publish a verified raw Go executable as `secret` (`secret.exe` on Windows), distinct
  from the Bash CLI, with a printed concrete absolute path for registration. Do not overwrite an existing Bash
  `secret`, modify PATH/profiles/client files automatically, register MCP, read stores, or prompt for values.
  Installation is not host activation; a raw executable is not the checkout launcher's per-exec rehash mechanism.
  State that difference explicitly.
- Bound HTTPS requests, redirects, response sizes and verifier runtime; allow only reviewed GitHub release hosts. Use
  new empty directories per downloaded input, scripts/readers outside them, Python `-I`, detached stdin and fixed
  diagnostics. Authenticate before chmod/version execution. Inspect ELF/Mach-O/PE architecture, assert `secret 0.3.0
  (go)`, rehash, then publish atomically without partial execution.
- User-owned private scratch/destination and bounded tokened locking are mandatory. Reject Unix aliases/unsafe modes
  and Windows reparse/unsafe DACL destinations; do not repair arbitrary existing parents. Handle Windows open-image
  replacement without delete-first/copy fallback. Never steal stale locks; retain manual recovery.
- Preserve Unix warm-offline rehash and cold-offline trust requirements: bundles alone do not bootstrap trust. Retain
  authenticated gh/TUF roots privately and test real offline verification after deleting cached binary/metadata, with
  network witnesses. New Windows offline behavior must be explicitly tested or reject cold offline installs; never
  silently skip attestation. No production fixture override.

## 4. MCP setup, bundle and metadata boundaries

- `docs/setup.md` is canonical: install, resolve absolute binary, obtain human-approved exact store references, merge
  registration, restart/reconnect, verify, update, rollback and remove only the installed binary/registration. Never
  delete stores. A paste-to-agent line links the version-pinned document, requires asking the human for intended
  references, and forbids discovering/reading stores or handling values.
- Every client command has argv equivalent to `ABSOLUTE_SECRET_GO mcp --store file:ABSOLUTE_STORE`, with repeated
  `--store` only for separately approved references. No bare `mcp`, wildcards, shell expansion, inferred default
  scopes, secret env values, or value-consuming `exec` wrapper. Provider references use their names-only manifests at
  the normal resolved directory; document explicit client SECRETS_DIR configuration for a nondefault directory.
- Supply Claude Code user-scope CLI, Claude Desktop JSON and MCPB, Codex CLI/desktop TOML/CLI, ChatGPT desktop,
  OpenCode command-array, Cursor JSON and VS Code snippets. Verify current first-party client schema/versions, config
  locations and restart behavior rather than copying sibling claims, especially ChatGPT sharing Codex config and VS
  Code personal config. If a client lacks local stdio, label it unsupported and show the supported local-client
  alternative, not a fictitious snippet or new bridge. Browser ChatGPT/remote connectors are not local process
  launchers.
- Test JSON/TOML/CLI examples with synthetic paths containing spaces, quotes and Windows backslashes, merge semantics
  and exact argv; prefer user scope, project scope only when asked. Agent setup must not run stash/get/operator
  consent or bypass guards.
- Existing server path: `internal/cli/features.go` mcp requires repeated explicit `--store`; `internal/feature/mcp.go`
  accepts 1-64 distinct exact references before reads, with absolute file: paths. Keep runtime code and
  protocol/schema unchanged. Tools are exactly list/show/diff/health, read-only hints, no values/mutations/
  resources/prompts/network listeners. Metadata includes keys, labels, presence, backend, references/paths and
  provider account IDs, not values/hashes/lengths. File metadata parsing can read local file bytes internally; this is
  not a claim that file contents are never opened. Provider metadata never calls value Get.
- MCP initialize currently reports `secret-metadata` version `1` and negotiates 2025-06-18 (also older supported
  versions). Health reports metadata schema version, readiness and configured store count, not release version,
  provider availability, value validity or hook protection. Obtain release version from CLI `version`. Document
  unauthenticated age outer metadata and metadata privacy explicitly.
- Bundle `secret-v0.3.0-desktop.mcpb`: macOS universal amd64/arm64 plus Windows amd64, following the reference's
  single cross-platform binary bundle. Windows arm64 CLI support does not imply Desktop-on-Arm support; no Linux
  Desktop bundle this release. Manifest 0.3 has required string `user_config.store_reference`, no default, passed as
  exactly one argv element: `["mcp","--store","${user_config.store_reference}"]`. Empty/malformed/relative file
  references fail; no shell, comma splitting, discovery or env credentials. First bundle supports one exact store;
  manual registrations support multiple. Required configuration must be validated before any metadata read.
- Bundle only manifest, LICENSE, reviewed icon and approved native payloads. Lock `@anthropic-ai/mcpb` (review
  reference 2.1.2 and its full lock/license/dependency graph), Node/npm/Python packaging versions and `npm ci
  --ignore-scripts`. Check ZIP traversal, duplicates, symlinks, sizes/modes, exact slices/PE machine and unpacked byte
  equality. Native extracted MCP tests are not actual Desktop user_config interpolation evidence. Require manual
  non-model Desktop install/config/restart evidence on disposable supported hosts before advertising extension
  compatibility; no real credentials.

  and committed checksums, inspect bundle, regenerate and byte-compare server.json, then publisher-validate its

## 10. Risks and unresolved evidence

- Full-set MCPB/universal-binary determinism is new; nondeterminism blocks freezing S, never justifies comparing fewer
  subjects. Packaging tools add dependency risk.
- Native Windows arm64 runner/gh availability, DACL-safe installer replacement and actual Desktop interpolation
  require new evidence, not inference from M5a amd64.
- Checksum plus adjacent bundle is not independent trust. Bootstrap script execution, gh/TUF and owner-authenticated C
  remain explicit trust roots; same-user tampering and TOCTOU are not solved by installers or extension packaging.
- Current client support, particularly ChatGPT desktop local stdio, is a verification dependency, not assumed truth
  from trello-mcp. No remote bridge is authorized.
- Registry namespace/OIDC acceptance, protected reviewers and disposable Desktop-host access need owner
  provisioning/approval at their checkpoints. Missing infrastructure blocks the applicable gate; it does not authorize
  credentials in chat or local hooks.
- A published release can precede a failed registry job. Report partial publication honestly, retain immutable bytes
  and recover only through the verified rerun path.
