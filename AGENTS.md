# Agent guidance

- Work in place. Today `bin/secret` is the Bash CLI, `hooks/guard-secrets` is the Claude Code and Codex guard, and `cmd/secret` is a Go module skeleton with `version` only. `skills/` carries agent guidance, `codex/` holds manual hook setup, `examples/` holds ripgrep config, `tests/` holds synthetic shell suites, and `.claude-plugin/`, `.codex-plugin/`, `.agents/plugins/` hold plugin manifests. Follow [ROADMAP.md](ROADMAP.md) and the [Go rewrite plan](docs/design/go-rewrite.md): target `internal/hook`, `internal/store`, `internal/backend`, `internal/transport`, `internal/feature`, `internal/secure`, and synthetic `testdata/` in later milestones. Do not assume these Go paths exist yet.
- Run shell tests with `bash tests/test-secret.sh` (CLI, Perl, Python 3, ripgrep), `bash tests/test-backends.sh` (stub), `bash tests/test-guard.sh` (jq), `bash tests/test-codex.sh` (Codex), `bash tests/test-libsecret.sh` (isolated Secret Service), and `bash tests/test-keychain.sh` (disposable macOS Keychain). Use the required-provider CI modes `SECRET_REQUIRE_LIBSECRET=1` and `SECRET_REQUIRE_KEYCHAIN=1` only in isolated provider environments. Run `shellcheck bin/secret hooks/guard-secrets tests/*.sh`; where available, run the shell suites with stock macOS `/bin/bash` 3.2 as well. Once Go exists, run `gofmt`, `go vet ./...`, `go test ./...`, and `go test -race ./...`, plus focused tests and the applicable shell suites for each change.
- Treat the GitHub Actions matrix as the gate. Open a PR or push a branch to trigger CI. `.github/workflows/ci.yml` runs Ubuntu/macOS shell suites, isolated providers and macOS Bash 3.2, plus Go checks on Ubuntu, macOS and Windows. The Go binary has not replaced the Bash CLI. Require green applicable runner jobs before calling a milestone complete.
- Keep `testdata/inventory/` exact: review regenerated keys and expectations for every intentional shell test change.
- Keep retained shell code Bash 3.2-compatible: avoid associative arrays, `mapfile`, `readarray`, `${var,,}`, and Bash 4-only features. Do not source credential stores. Preserve quoted expansions and private atomic writes.
- Keep secret values as `[]byte` in Go, never in errors, logs or argv. Put table-driven synthetic tests in the same commit as each behavior change; do not weaken a guard expectation without a classified reason and reviewed tightening/differential record. Regenerate stash byte fixtures with `bash testdata/store/gen.sh OUTPUT_DIR`, compare against `testdata/store/golden/`, and keep the provider directory stub in test files only. A killed Go writer leaves a tokened `.write-lock` for manual verification and removal, never automatic stealing. The next lock owner cleans marked private scratch; do not use a real store for tests.
- Never read, inspect or use real credentials or stores. Use synthetic fixtures and disposable provider targets only. Do not touch a user's actual Keychain or keyring, or install hooks on the host.
- Keep commits conventional and lowercase (`type(scope): summary`), signed, and free of co-author trailers. Write no em or en dashes and no emojis. Update [ROADMAP.md](ROADMAP.md), [CHANGELOG.md](CHANGELOG.md) and relevant documentation in the same PR as changed behavior. Do not commit or push unless asked.

The security model is accident prevention, not a sandbox: the CLI supplies selected values to a child and redacts literal output; the hook denies known secret-reading operations but cannot contain a determined agent, transformed values, unobserved tools or arbitrary child behavior. Do not claim fail-closed host protection without host evidence. Report potential value leaks privately with synthetic reproduction only; see [SECURITY.md](SECURITY.md).
