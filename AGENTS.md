- Keep retained shell code Bash 3.2-compatible: avoid associative arrays, `mapfile`, `readarray`, `${var,,}`, and Bash 4-only features. Do not source credential stores. Preserve quoted expansions and private atomic writes.
- Keep secret values as `[]byte` in Go, never in errors, logs or argv. Put table-driven synthetic tests in the same commit as each behavior change; do not weaken a guard expectation without a classified reason and reviewed tightening/differential record. Regenerate stash byte fixtures with `bash testdata/store/gen.sh OUTPUT_DIR`, compare against `testdata/store/golden/`; regenerate CLI cases with `bash testdata/cli/gen.sh OUTPUT_DIR` and compare against `testdata/cli/golden/`, and keep the provider directory stub in test files only. A killed Go writer leaves a tokened `.write-lock` for manual verification and removal, never automatic stealing. The next lock owner cleans marked private scratch; do not use a real store for tests.
- Never read, inspect or use real credentials or stores. Use synthetic fixtures and disposable provider targets only. Do not touch a user's actual Keychain or keyring, or install hooks on the host.
- Keep commits conventional and lowercase (`type(scope): summary`), signed, and free of co-author trailers. Write no em or en dashes and no emojis. Update [ROADMAP.md](ROADMAP.md), [CHANGELOG.md](CHANGELOG.md) and relevant documentation in the same PR as changed behavior. Do not commit or push unless asked.

The security model is accident prevention, not a sandbox: the CLI supplies selected values to a child and redacts literal output; the hook denies known secret-reading operations but cannot contain a determined agent, transformed values, unobserved tools or arbitrary child behavior. Do not claim fail-closed host protection without host evidence. Report potential value leaks privately with synthetic reproduction only; see [SECURITY.md](SECURITY.md).
